# Фикстуры: мини-каталог фестиваля

Канонический детерминированный набор данных, на который ссылаются сценарии (по **именам**, а не «какие-то концерты»). Загружается из `environment.py`/`Предыстория`. Время — через `FestivalClock`. Конкретные файлы данных (YAML/JSON/SQL) живут рядом; ниже — их смысл.

## Залы и переходы

| Зал | Назначение |
|-----|------------|
| A | опорный зал в сценариях переходов |
| B | переход A↔B = **15 мин** (для hurry/tight/ok) |
| C | переход A↔C = **0 мин** (same_hall) |
| D | переход A↔D — **нет данных** (no_data) |
| E | переход A↔E = **1 мин** (same_building) |

Все переходы хранятся в обе стороны (см. [02](../02-domain-model.md)).

## Дни фестиваля

Три дня: `2026-07-01`, `2026-07-02`, `2026-07-03`. Старт продаж и опорные метки времени задаются часами в сценарии (offset/accelerated).

## Концерты (примерный срез)

- Набор концертов с разными `starts_at`/`duration`, залами A–E, жанрами и ценами.
- Концерт **«хедлайнер»** (`Artist.is_special = true`) — для кривой распродажи (раскупается раньше).
- Концерт **«обычный»** — контраст к хедлайнеру.
- Концерт **«K»** — используется в сценариях наличия/листа/уведомлений (распродаётся, порождает alert).

## Программы (повторы)

- Программа **«P»** назначена двум разным концертам → проверка детекта повтора (`Program.signature`).
- Прочие концерты имеют уникальные программы.

## Авторы/жанры

- Автор **«Бах»** — для сценариев «любимый автор → бонус».
- Несколько жанров для проверки разнообразия/фильтра окон.

## Покупки (для sim_replay)

- Для концерта «K»: вместимость 5, и 3 покупки с `purchased_at ≤ 2026-06-20` → остаток 2 на эту дату (см. `availability.feature`).

## Принципы

- **Детерминизм:** фиксированные значения и seed; никакой случайности без seed.
- **Минимальность:** ровно столько сущностей, сколько нужно сценариям; не «весь фестиваль».
- **Именованность:** сущности адресуются по стабильным именам (A/B/C/D/E, «K», «P», «Бах», «хедлайнер»).
