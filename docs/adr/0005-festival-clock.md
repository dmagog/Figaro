# 0005 — Управляемое время через FestivalClock

- Статус: accepted
- Дата: 2026-05

## Контекст

Наличие, фазы фестиваля, напоминания зависят от «сейчас». v2 звал `datetime.now()` напрямую → невозможно отлаживать в состоянии «за N дней до фестиваля», ускорять время или тестировать уведомления.

## Решение

Единый провайдер времени **`FestivalClock`** с режимами `real` / `offset` / `accelerated` (tz-aware). Прямой вызов `datetime.now()/utcnow()/time.time()` в `domain`/`services` запрещён (линт-правило). Состояние часов персистентно (`ClockState`).

## Последствия

- (+) Детерминированные тесты времени; дев/демо в любой точке таймлайна; нагрузочный тест и проверка уведомлений в ускоренном режиме за минуты.
- (+) Один тикер двигает наличие и уведомления (см. [0002](0002-no-broker-in-mvp.md)).
- (−) Дисциплина: всё время — только через провайдер; нужен линт/код-ревью-гейт.
