# 0002 — Без брокера сообщений в MVP

- Статус: accepted
- Дата: 2026-05

## Контекст

v2 тащил RabbitMQ + Celery + Flower, но реальная нагрузка — десятки одновременных запросов, а тяжёлый расчёт маршрутов делается офлайн. Брокеры там были инфраструктурой без задачи. При этом письма/напоминания нужны.

## Решение

В MVP брокера нет. Уведомления — через таблицу-**outbox** + лёгкий планировщик (APScheduler), один на инстанс (отдельный процесс/сервис `scheduler` или лидер через `pg_try_advisory_lock`). Точки постановки событий не знают про транспорт.

## Последствия

- (+) Проще стек и эксплуатация; меньше точек отказа.
- (+) «Готово к брокеру»: диспетчер outbox заменяется на Celery+broker без изменения доменного кода.
- (−) Нет распределённой обработки задач; единый тикер — узкое место при большом росте (приемлемо для нашего масштаба).
- Брокер вводим вместе с Telegram-ботом и массовыми рассылками (зона роста).
