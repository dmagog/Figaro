# 0006 — Аккаунты + реальный RBAC (user/researcher/admin)

- Статус: accepted
- Дата: 2026-05

## Контекст

v2: вход по email/паролю, но `role` был косметикой — всё гейтилось бинарным `is_superuser`, `observer` не имел доступа, UI смены ролей не было. Нужны три осмысленные персоны: зритель, исследователь (аналитика/маркетинг), администратор (системы, пересчёты, пульт эмуляции).

## Решение

Идентификация — аккаунты (логин/пароль). Роль — enum `user | researcher | admin`, проверяется единой зависимостью `require_role(*roles)`. Роли назначает admin через UI. Матрица доступа зафиксирована в [05](../05-architecture-and-platform.md#роли-и-доступ-rbac). Экраны исследователя резервируются, но реализуются в зоне роста.

## Последствия

- (+) Чёткие границы прав с первого дня; не нужно ретрофитить RBAC.
- (+) Проверка владения ресурсом (свой `RouteSheet`) — в одном месте (`web/deps.py`).
- (−) Анонимный быстрый старт не выбран (был альтернативой) → чуть выше барьер входа; компенсируется коротким онбордингом.
- Приватность/ПДн при работе с аккаунтами и покупками — [08](../08-cross-cutting.md#приватность-и-персональные-данные-152-фз).
