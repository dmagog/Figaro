# Changelog

Версионирование итеративное; мажор = **3** (третья итерация сервиса). Минор растёт с каждым завершённым этапом [дорожной карты](docs/06-mvp-roadmap.md).

## [3.12.0] — Веб: регистрация и верификация почты
- `web/routes.py` + шаблоны `register.html`/`register_done.html`/`verify.html`: регистрация (email, имя, пароль, согласие на ПДн через `auth.register`), `/verify` по токену (`auth.verify_email`). Почтового транспорта пока нет (no-op outbox) — ссылка верификации показывается на экране (dev); вход не блокируется отсутствием подтверждения (домен так и работает). Ссылка «Регистрация» со страницы входа.
- `@web`-тесты: согласие обязательно, регистрация→верификация→вход, занятый email. Тесты: pytest 68/68, behave 117 (15 фич, 4 `@growth`).
- Этим закрыт инкремент 2 веб-слоя (анкета + пульт + регистрация).

## [3.11.0] — Веб: админский пульт эмуляции (FestivalClock + наличие)
- `web/app.py`: общий `FestivalClock` на `app.state` (по умолчанию real, в памяти; при заданном `clock_path` переживает рестарт — load на старте, save при изменении). В тестах `clock_path=None` → на диск не пишем.
- `web/routes.py` + `pult.html`: экран `/admin/pult` (RBAC `can_access(role,"пульт эмуляции")` = только admin): управление часами (real/offset/accelerated, прыжок виртуального времени, множитель), режимом наличия (`sim_curve`/`sim_replay` + seed) с пересчётом под виртуальное время (`availability.tick`), ручной пересчёт и сброс к началу продаж. Сводка: фаза фестиваля, в продаже/распродано. Ссылка «Пульт» в навигации видна только admin.
- `@web`-тесты: не-admin → 403, admin меняет часы (offset), пересчёт пишет снимки. Тесты: pytest 65/65, behave 117. Живой прогон: перевод на середину фестиваля + `sim_curve` → 46 в продаже / 54 распродано; сброс → 100.

## [3.10.0] — Веб: анкета холодного старта в подборе
- `services/recommend.py`: персистентность анкеты — `save_preferences` (upsert `UserPreferences` по составному ключу user+festival), `load_prefs` (id любимых авторов/жанров → имена для бонуса), `profile_for_user` (сохранённая анкета → `WeightProfile`, иначе дефолт).
- `web/routes.py` + `questionnaire.html`: экран анкеты (темп, вектор интереса, любимые авторы), сохранение и редирект в подбор. `/recommend` теперь учитывает анкету: веса comfort/diversity, бонус за любимых авторов и фильтр по числу концертов от темпа (релаксация, если пусто). Подсказка-CTA «заполнить анкету», метка «настроено по вашей анкете».
- `@web`-тесты: GET анкеты, влияние темпа на выдачу (баланс/марафон/расслабленно). Тесты: pytest 62/62, behave 117. Живой прогон: 58 авторов в форме, темп меняет число карточек (11/24/12).

## [3.9.0] — Веб-слой: первый срез (подбор + маршрутный лист)
- `web/app.py`: фабрика `create_app(engine=None)` (движок резолвится на старте через lifespan — импорт модуля не требует драйвера БД; для sqlite-dev таблицы создаются на старте, в Postgres — Alembic), обработчики `CsrfError`/`Forbidden` → 403.
- `web/deps.py`: сессия БД на запрос (коммит/откат), текущий пользователь из cookie-сессии, CSRF (double-submit cookie + скрытое поле формы).
- `web/routes.py` + шаблоны (Jinja2, Pico.css, htmx): упрощённый вход/выход (по сид-пользователям, без email-верификации), подбор маршрутов (карточки по архетипам, дефолтные веса), маршрутный лист (создание из маршрута/с нуля, добавление/удаление/закрепление, подсказки концертов и офф-программы) — HTMX-обновление без перезагрузки.
- `web/devseed.py`: демо-сидинг (реальный каталог из Excel → предрасчёт → активный фестиваль + демо-аккаунты; покупки пропускаются — их даты требуют аудита, docs/05).
- Веб тонкий: вся логика — в services/*; экраны лишь её показывают (ADR 0001).
- `@web` smoke-тесты (FastAPI TestClient): вход/CSRF/сессия, подбор показывает карточки, лист редактируется. Тесты: pytest 60/60, behave 117 сценариев (15 фич, 4 `@growth`). Проверен живой прогон на реальном каталоге (3 архетипа, 24 карточки).

## [3.8.0] — Офф-программа: импорт и подсказки (зона роста)
- `importing/source.py`: `OffProgramRow` + `CatalogSource.off_program`; `offprogram_from_excel(data_dir)` парсит `Offprogram-good.xlsx` (EventNum/EventName/Description/EventDate/EventLong/HallName/Format/Recommend/link), `_long_to_min` («HH:MM[:SS]» → минуты); `from_excel` теперь подтягивает офф-программу.
- `importing/seed.py`: секция 9 — импорт внепрограммных событий в рамках `festival_id`, идемпотентно по `external_num` (привязка зала по имени, устойчивый парсинг дат).
- `services/sheets.py`: `OffProgramSuggestion` + `suggest_off_program(session, sheet)` — внепрограммные события, помещающиеся в щели маршрута (переиспользует `_fits_gap`); рекомендованные ранжируются выше.
- BDD: зелёная `off_program` (импорт со скоупом и флагом рекомендации, идемпотентность, подсказка в щель, ранжирование рекомендованных, отсев накладок). Тесты: pytest 54/54, behave 117 сценариев (15 фич, 4 `@growth` отложены). Реальная выгрузка офф-программы парсится в pytest.

## [3.5.0] — Этап 5: наличие и эмуляция

## [3.2.0] — Этап 2: движок маршрутов
- Конфликты переходов (`routing/conflicts.py`): статусы ok/tight/hurry/overlap/same_hall/same_building/no_data, пороги из конфига, резолв walk (матрица → координатная оценка по `walk_speed` → no_data).

- BDD: зелёные `transitions`, `route_engine` и отложенные ранее `@stage2`-активации `festival_lifecycle`. Тесты: pytest 25/25, behave 42 сценария.
